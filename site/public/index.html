    Cloudflake core simulation APIs and Miniflare Workers adapter primitives
    API Behavior
    simulate / campaign Run one seeded schedule or explore thousands of seeds with aggregated Antithesis property coverage (always, sometimes, reachable, unreachable) and failure bucketing.
    sim.deliver / sim.profile Inject seeded latency distributions (uniform, exponential, pareto, bimodal), zero-step drops, 1..maxDuplicates extra deliveries, ambiguous gray failures, and per-seed swarm fault regimes.
    simulatedQueue / Alarm / KV / DO In-process simulators for multi-message Queue batches + DLQ, exponential-backoff alarms, stale KV reads + TTLs, DO eviction / abort / input gates, waitUntil drops, and outbound fetch faults.
    HistoryRecorder / checkLinearizability Wing-Gong linearizability checker supporting definite ok/fail and indeterminate ambiguous outcomes against a pure sequential reference model.
    minimizeFaults / exploreMultiverse Delta-debug a failing seed to the minimal subset of injected faults that still reproduces the bug, or branch from snapshots guided by coverage edges and assertions.
    probe / probeWorkers Local exploratory probers (auto-skip in CI unless CLOUDFLAKE_PROBE=1) that run time-budgeted campaigns, bucket failures, minimize faults, and print agent-ready diagnostic guidance.
    simulateWorkers / createBindingProxies Run real bundled Workers in workerd with drop-in Queue, KV, and Durable Object RPC proxies, synced virtual time (controlServiceBinding), outboundFaultService, and doNemesis eviction chaos.

    Explore 1,000 duplicate-delivery queue schedules in milliseconds. Remove the posted.has(id) guard to prove the invariant catches double-posting, then replay the failing seed.

    await campaign({ seed: 0, runs: 1000 }, payments)
    Seeded virtual delivery Injected duplicate fault (delta-debugged by minimizeFaults) 
    import assert from 'node:assert/strict'
import { campaign, simulate, simulatedQueue } from 'cloudflake'

async function payments(sim) {
  const posted = new Set()
  let balance = 0
  const queue = simulatedQueue(
    sim,
    'payments',
    ({ messages }) => {
      for (const { id, body } of messages) {
        if (posted.has(id)) continue // remove to see seed=17 fail
        posted.add(id)
        balance += body.amount
      }
    },
    { duplicate: 0.5 },
  )

  sim.invariant('one posting per payment', () => assert.equal(balance, 7 * posted.size))
  for (let i = 0; i < 8; i++) await queue.send({ amount: 7 })
  sim.onIdle('all payments settled', () => assert.equal(balance, 56))
}

await campaign({ seed: 0, runs: 1000 }, payments)
await simulate({ seed: 42, onStep: console.log }, payments)

import { simulateWorkers } from 'cloudflake/miniflare'

await simulateWorkers(

    modules: true,
    scriptPath: './build/worker.mjs',

    Interleave concurrent clients across I/O checkpoints, inject eventually consistent KV stale reads and ambiguous gray RPC resets, and verify every history with checkLinearizability.

    checkLinearizability(history.entries, counterModel) 
    import assert from 'node:assert/strict'
import { HistoryRecorder, checkLinearizability, client, simulate } from 'cloudflake'

await simulate({ seed: 9 }, async (sim) => {
  const history = new HistoryRecorder(sim)
  let total = 0

  await Promise.all([
    client(sim, 'A', async (cp) => {
      const op = history.invoke('A', 'add', 5)
      const seen = total
      await cp(2, 'A after read')
      total = seen + 5
      history.complete(op, 'ok', total)
    }),
    client(sim, 'B', async (cp) => {
      const op = history.invoke('B', 'add', 10)
      const seen = total
      await cp(1, 'B after read')
      total = seen + 10
      history.complete(op, 'ok', total) // or 'indeterminate' on gray RPC reset
    }),
  ])

  sim.onIdle('linearizable', () => {
    const res = checkLinearizability(history.entries, {
      init: () => 0,
      step: (s, op, arg) => [s + arg, s + arg],
    })
    assert.ok(res.linearizable, res.explanation)
  })
})

    Draw workload values and the Cloudflake scheduling seed with Hegel so Hegel shrinks individual inputs and the delivery order simultaneously.

    npm run test:hegel 
    import assert from 'node:assert/strict'
import { testAsync } from '@hegeldev/hegel'
import * as g from '@hegeldev/hegel/generators'
import { simulate, simulatedQueue } from 'cloudflake'

await testAsync(
  async (tc) => {
    const amounts = tc.draw(
      g.arrays(g.integers({ minValue: 1, maxValue: 1000 }), { minSize: 1, maxSize: 12 }),
    )
    const seed = tc.draw(g.integers({ minValue: 0, maxValue: 0xffffffff }))

    await simulate({ seed }, async (sim) => {
      const seen = new Set()
      let settled = 0
      const q = simulatedQueue(sim, 'payouts', ({ messages }) => {
        for (const { id, body } of messages) {
          if (seen.has(id)) continue
          seen.add(id)
          settled += body.amount
        }
      }, { duplicate: 1 })

      for (const amount of amounts) await q.send({ amount })
      const expected = amounts.reduce((a, b) => a + b, 0)
      sim.onIdle('exact sum', () => assert.equal(settled, expected))
    })
  },
  { testCases: 100 },
)

    Swarm fault regimes

    Three ways Cloudflake breaks your edge app

    • At-least-once & reordering: duplicates Queue batches, retries alarms with backoff, and varies latency across uniform, exponential, pareto, and bimodal distributions.
    • Eviction & ephemeral loss: doNemesis evicts Durable Objects mid-flight and simulatedWaitUntil drops background tasks before completion.
    • Stale reads & gray failures: simulatedKV serves stale edge values during propagation lag and ambiguous resets commit server-side before returning an error.

    Call sim.heal() (or pass healAt) to pause chaos cleanly so retries drain before sim.onIdle() convergence assertions run.

    Questions

    Before you run your first campaign

    How fast is the in-process scheduler?
    The core scheduler runs in process on Node 24+ with zero runtime dependencies over a binary-heap event calendar—around 4.9 million events per second on the isolated benchmark—so thousands of model seeds finish in seconds.
    Does a seed replay workerd runs identically?
    Cloudflake controls virtual time, PRNG streams, scheduled events, checkpoints, and controlServiceBinding hooks (Date.now(), new Date(), Math.random(), crypto.randomUUID(), alarms, and waitUntil). Native workerd internals outside those hooks need injected clocks, entropy, or service doubles for exact replay.
    How does Cloudflake pair with Hegel?
    Draw both your workload values (amounts, payloads, operation lists) and the Cloudflake scheduling seed with @hegeldev/hegel so Hegel shrinks both together. Save the minimized inputs alongside the failing seed for permanent regressions.
    How should I split CI tests vs. local probing?
    Keep fixed small-seed campaign() runs and regression seeds in CI. Put longer exploratory probe() and probeWorkers() scripts locally—they skip automatically when CI is set unless you pass CLOUDFLAKE_PROBE=1.
