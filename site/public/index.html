Cloudflake core simulation APIs and Miniflare Workers adapter primitives
API Behavior
simulate / campaign Run one seeded schedule or explore thousands of seeds with aggregated Antithesis property coverage (always, sometimes, reachable, unreachable) and failure bucketing.
sim.deliver / sim.profile Inject seeded latency distributions (uniform, exponential, pareto, bimodal), zero-step drops, 1..maxDuplicates extra deliveries, ambiguous gray failures, and per-seed swarm fault regimes.
simulatedQueue / Alarm / KV / DO In-process simulators for multi-message Queue batches + DLQ, exponential-backoff alarms, stale KV reads + TTLs, DO eviction / abort / input gates, waitUntil drops, and outbound fetch faults.
HistoryRecorder / checkLinearizability Wing-Gong linearizability checker supporting definite ok/fail and indeterminate ambiguous outcomes against a pure sequential reference model.
minimizeFaults / exploreMultiverse Delta-debug a failing seed to the minimal subset of injected faults that still reproduces the bug, or branch from snapshots guided by coverage edges and assertions.
probe / probeWorkers Local exploratory probers (auto-skip in CI unless CLOUDFLAKE_PROBE=1) that run time-budgeted campaigns, bucket failures, minimize faults, and print agent-ready diagnostic guidance.
simulateWorkers / createBindingProxies Run real bundled Workers in workerd with drop-in Queue, KV, and Durable Object RPC proxies, synced virtual time (controlServiceBinding), outboundFaultService, and doNemesis eviction chaos.

In-process model test

Explore 1,000 schedules in milliseconds

Verify queue idempotency before spinning up a runtime. Remove the posted.has(id) guard to prove the campaign catches duplicate deliveries, then replay the failing seed. 

import assert from 'node:assert/strict'
import { campaign, simulate, simulatedQueue } from 'cloudflake'

async function payments(sim) {
  const posted = new Set()
  let balance = 0
  const queue = simulatedQueue(sim, 'payments', ({ messages }) => {
    for (const { id, body } of messages) {
      if (posted.has(id)) continue
      posted.add(id)
      balance += body.amount
    }
  }, { duplicate: 0.5 })

  sim.invariant('one posting', () => assert.equal(balance, 7 * posted.size))
  for (let i = 0; i < 8; i++) await queue.send({ amount: 7 })
  sim.onIdle('settled', () => assert.equal(balance, 56))
}

await campaign({ seed: 0, runs: 1000 }, payments)
await simulate({ seed: 42, onStep: console.log }, payments)

Real Workers & Hegel

Drive real bindings in workerd

Graduate to SQLite Durable Objects, R2, D1, and Queues with cloudflake/miniflare—or pair with Hegel to shrink workload inputs and scheduling seeds together. 

import assert from 'node:assert/strict'
import { simulateWorkers } from 'cloudflake/miniflare'

await simulateWorkers(
  { seed: 42 },
  () => ({
    modules: true,
    scriptPath: './build/worker.mjs',
    compatibilityDate: '2026-07-01',
    durableObjects: { BOOK: { className: 'Book', useSQLite: true } },
    r2Buckets: ['FILES'],
  }),
  (sim, runtime) => {
    sim.deliver('upload invoice 17', async () => {
      const res = await runtime.dispatchFetch(
        'https://app.test/invoices/17',
        { method: 'PUT', body: 'invoice data' },
      )
      assert.ok(res.ok)
    }, { maxDelay: 50, duplicate: 1 })

    sim.onIdle('one stored invoice', async () => {
      const bucket = await runtime.getR2Bucket('FILES')
      assert.equal((await bucket.list()).objects.length, 1)
    })
  },
)

Questions

Before you run your first campaign

How fast is the in-process scheduler?
The core scheduler runs in process on Node 24+ with zero runtime dependencies over a binary-heap event calendar—around 4.9 million events per second on the isolated benchmark—so thousands of model seeds finish in seconds.
Does a seed replay workerd runs identically?
Cloudflake controls virtual time, PRNG streams, scheduled events, checkpoints, and controlServiceBinding hooks (Date.now(), Math.random(), crypto.randomUUID(), alarms, and waitUntil). Native workerd internals outside those hooks need injected clocks, entropy, or service doubles for exact replay.
How does Cloudflake pair with Hegel?
Draw both your workload values (amounts, payloads, operation lists) and the Cloudflake scheduling seed with @hegeldev/hegel so Hegel shrinks both together. Save the minimized inputs alongside the failing seed for permanent regressions.
How should I split CI tests vs. local probing?
Keep fixed small-seed campaign() runs and regression seeds in CI. Put longer exploratory probe() and probeWorkers() scripts locally—they skip automatically when CI is set unless you pass CLOUDFLAKE_PROBE=1.
